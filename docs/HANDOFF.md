# Moving computers and continuing work

Last documented: 30 September 2026. These instructions belong to the project, not a particular laptop or chat history.

## What to take with you

Copy or back up the project with:

- AGENTS.md and README.md.
- docs/, including design-reference/ screenshots and the original HUD concept.
- src/, index.html, package.json, and package-lock.json.
- public/, including the full original icon and every exported icon size.
- reference-1.jpg and reference-2.jpg.
- .gitignore and any future project configuration.

node_modules/ can be recreated. dist/ is generated by the build and can be recreated. output/ contains historical checks, screenshots, and the earlier mockup; keep it if you want that work history, but the required design references now also live in docs/design-reference/.

There is no .git directory in the current project snapshot, so this folder is not presently a Git repository. A .gitignore file alone does not create version history or a remote backup. No repository was initialized or published as part of this documentation task.

## Start on the new computer

1. Put the project in any folder. The folder does not need the old home-deco-sim name.
2. Install Node.js/npm compatible with the project's dependencies.
3. Open a terminal in the project folder and run:

       npm ci
       npm run dev

4. Open the URL printed by Vite. It may choose another port if the default port is already in use.
5. Verify a production build:

       npm run build
       npm run preview

Use npm ci to install the exact lockfile graph, rather than deleting the lockfile or upgrading packages during a computer move.

Recorded development environment: Node v23.6.0, npm 10.9.2, Vite 6.4.3, Three.js 0.170.0. These are the observed versions on the current machine, not a claim that this runtime is the latest or the preferred long-term version. Runtime pinning and portability checks are Phase 1 work.

The game itself does not need Codex caches, Python, an image-generation tool, or a remote service to run. Its icon files and procedural art are already in the project.

## Saved rooms are separate from the project

The game currently has one save in browser localStorage at key home-deco-sim:room. Copying the source folder does not copy that saved room. Changing browsers, profiles, hostnames, or ports can also make the old save unavailable at the new origin.

There is no export/import button today. Phase 2 adds one. Until then, if you need to preserve a saved layout:

1. In the old browser, click Save room.
2. Open browser developer tools, find Local Storage for the game's origin, and copy the value of home-deco-sim:room into a plain JSON text file.
3. Keep that JSON file separately with your backup.
4. In the new browser, open the game and click Save room once to create the storage key.
5. In developer tools, replace that key's value with the backed-up JSON, then click Load.

Use the loader to validate the restored layout. The current room is 8 × 8; layouts with out-of-bounds coordinates are rejected. If restoring fails, retain the backup and diagnose the mismatch instead of deleting it.

No cloud synchronization or automatic browser-save transfer is implemented.

## Validation on any computer

There is no npm test script yet. The files under output/checks recorded previous browser checks, but contain absolute paths to this machine's bundled Node packages and Microsoft Edge. They will not run unchanged on an arbitrary laptop. Phase 1 should replace them with a project-local runner.

Until then, run npm run build and check the relevant scenarios below in the browser.

| Scenario | Expected result |
| --- | --- |
| Place furniture on a free tile | Item is added; count updates; selected controls appear |
| Place on an occupied tile | No overlapping furniture is committed |
| Drag onto a free / blocked tile | Valid move commits; blocked move restores old location |
| Rotate near another item or boundary | Valid rotation commits; invalid rotation is rejected |
| Change upholstery or plant pot | Only marked parts change color |
| Save, modify, then Load | Saved layout, rotation, finishes, and colors return |
| Invalid save data | Current room remains intact and feedback appears |
| Search plant / use categories | Five plant choices appear; category filtering is correct |
| Type R/Delete in search | Search edits normally; game shortcuts do not fire |
| Toggle grid, walls, and camera view | Each control works and remains reachable |
| Clear room | Items and occupancy clear; UI count updates |
| Choose furniture on a phone | Drawer collapses for placement |
| Select furniture on a phone | Controls dock outside the room in the drawer |
| Hide/Browse and orientation change | Viewport resizes without stranded or overlapping controls |
| Drag with one finger | Furniture moves without orbiting the camera |
| Pinch/orbit with two fingers | Camera changes without an accidental furniture drag |
| Resize with a selected item | Controls move between viewport and drawer correctly |
| Branding | Little Nest title/header and icon load; no missing asset requests |

Baseline viewport checks: 320 × 568, 390 × 844, 768 × 1024, 568 × 320, 844 × 390, and 1440 × 900. Inspect the actual phone when available; browser emulation does not cover every mobile behavior.

Current browser checks previously passed placement, saving, plants, HUD/touch interaction, and branding. The production build passes with a bundle-size advisory. That advisory is not a failed build; prioritize measured performance work rather than changing the architecture only to silence it.
